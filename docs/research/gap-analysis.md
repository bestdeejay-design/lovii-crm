## 2. Подтверждённые разрывы (никто не закрывает полностью)

### G1. Франшиза «под ключ» в одной системе
Управление франшизой (роялти + стандарты/аудиты + централизованные закупки + обучение + онбординг точек) разорвано между дорогим Enterprise-тарифом iiko [1](https://iikoservice.ru/), экспортными механиками r_keeper [2](https://eto-razvod.ru/review/rkeeper/) и внешними MD Audit/CheckOffice [3](https://checkoffice.ru/blog/poleznye-materialy/kak-delegirovat-kontrol-kachestva-v-restorane-i-ne-poteryat-standarty/). Никто не считает роялти автоматически от фискальной выручки внутри кассовой системы.

### G2. Отзыв как операционные данные
Все системы собирают отзывы отдельно от операций. Связка «оценка ↔ конкретное блюдо ↔ смена ↔ курьер» не реализована ни у кого (внешние типа getMeBack собирают оценки после оплаты, но не имеют данных склада/кухни [4](https://getmeback.ru/business/restaurants/)). Это прямой путь к управлению качеством, которого нет на рынке.

### G3. Микробизнес без «корпоративного порога»
Глубина корпоративного класса (автозаказ по прогнозу, фудкост-аналитика, видеоконтроль, контроль свежести) доступна только в старших тарифах за 8–10+ тыс ₽/мес за кассу [1](https://iikoservice.ru/), а МСБ-системы урезают лимитами (100 техкарт на €29 у Poster [5](https://hf.ru/services/poster_pos)). Точки между ними — «маленькая франшиза» — не обслужены никем.

### G4. Единый профиль гостя без интеграционных швов
Единая карточка гостя — либо результат интеграций с внешними CRM (ReMarked и др.) [6](https://remarked.ru/effectively-involve-guests-in-the-restaurant-loyalty-program), либо отсутствует. Встроенные лояльности касс не склеивают каналы (зал/доставка/агрегатор) в одну историю.

### G5. Курьерская логистика как часть операционного контура
Приложения курьеров и диспетчеризация либо примитивны внутри касс, либо покупаются отдельно (ЯКурьер, EDICourier, Яндекс Маршрутизация) [7](https://toolfox.ru/services/programmy-dlya-dostavki-edy); экономика доставки (маржа против агрегаторов) не считается системно.

### G6. Прослеживаемость партий «до чека»
Событийная модель остатков с трассировкой «партия сырья → заготовка → блюдо → чек гостя» отсутствует как продукт; журналы ХАССП живут в отдельных сервисах чек-листов [8](https://serviceinspector.ru/publiccatering).

### G7. Онбординг точки «за день»
Ни у кого нет версионируемого «шаблона точки» (меню+ТТК+цены+права+чек-листы+нормативы), клонируемого в пару кликов с каталогом готовых рецептур (приём на 3 000 блюд у Saby [9](https://saby-sbis.ru/blog/programmy-dlya-avtomatizacii-obshchepita-podborka-dlya-kafe-i-restorana) — единственная близкая практика).

## 3. Что делать с разрывами — стратегия продукта

| Разрыв | Продуктовый ответ |
|---|---|
| G1 | Франшиза как режим работы платформы с первого дня: УК → франчайзи → точка; роялти из фискальных данных |
| G2 | Отзывы как события, привязанные к заказу/смене/курьеру + автозадачи сервис-рекавери |
| G3 | «Корпоративные» модули доступны на любом тарифе; монетизация от точек и оборота, а не от функций |
| G4 | Встроенный гостевой контур: склейка каналов, лояльность на кассе, кампании по RFM |
| G5 | Свой модуль доставки + приложение курьера; роутинг по API провайдеров; отчёт маржи по каналам |
| G6 | Событийная модель склада с трассировкой партий; ХАССП-чек-листы поверх данных склада |
| G7 | Версионируемый шаблон точки + библиотека ТТК бренда → онбординг за часы |

Полная сборка ответов — в [`product-blueprint.md`](product-blueprint.md).
