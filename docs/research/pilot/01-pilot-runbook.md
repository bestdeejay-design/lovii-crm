# Пилот 01. Ранбук пилотного среза: приложение + касса + чеки + мини-кабинет

> **Статус: фаза 27 · 10.10.2026.** Срез собран в [`/pilot/`](https://bestdeejay-design.github.io/lovii-crm/pilot/) репозитория; это рабочий продукт среза, а не макет — данные живут в журнале событий браузера и переживают перезагрузку.

> Пилот запускает **часть** платформы по решению команды: гостевое приложение, кассовое место, фискальные чеки и мини-кабинет бизнеса. Всё остальное (кухня-тайминги, доставка, УК) остаётся в демо и подключается следующими срезами.

## 1. Что входит в срез

| Рабочее место | Где | Что умеет |
|---|---|---|
| Гость | вкладка «Гость · приложение» | меню по категориям, корзина, заказ с телефоном и согласием (152-ФЗ), статусы заказа `new → accepted → kitchen → ready → served` |
| Кассир | вкладка «Касса» | очередь заказов в три колонки, приём/готовка/выдача, оплата картой и наличными, чек с реквизитами ФФД 1.2, открытие/закрытие смены (Z-отчёт) |
| Владелец/управляющий | вкладка «Бизнес · мини-кабинет» | выручка дня, средний чек, заказы по каналам, журнал событий шины, меню и стоп-лист с мгновенной раскаткой, настройки точки, закрытые смены |

Контракты, по которым собран срез: статусы — канонический словарь ([`../components/12-data-model.md`](../components/12-data-model.md), §0); чек — реквизиты ФФД 1.2 ([`../components/01-pos-fiscal.md`](../components/01-pos-fiscal.md)); оплата — контракт мок-банка ([`../infrastructure/banks-kassa-ofd.md`](../infrastructure/banks-kassa-ofd.md), §7).

## 2. Запуск

1. Открыть [страницу пилота](https://bestdeejay-design.github.io/lovii-crm/pilot/) (или `pilot/index.html` в репозитории).
2. Вкладка «Касса»: **открыть смену** (без смены чек пробить нельзя — это тоже проверяемое поведение).
3. Вкладка «Гость»: собрать корзину, указать телефон (необязательно), отправить заказ.
4. На кассе принять заказ → «Готово» → «Выдать» → оплатить. Чек появится в списке; через 2–4 секунды статус ОФД сменится на «в ФНС».
5. В мини-кабинете видно выручку и заказы; стоп-лист, включённый там, мгновенно убирает позицию из гостевого меню.

Две вкладки на одном устройстве синхронизируются в реальном времени (событийная шина через `BroadcastChannel`) — можно держать гостя и кассу рядом.

## 3. Что настоящее, а что эмулируется

| Контур | В пилоте | В боевом запуске |
|---|---|---|
| Данные | журнал событий в браузере устройства | тот же контракт событий + сетевой адаптер (многоустройственность) |
| Банк | мок: авторизация 0,7 с, отказ по правилу «сумма кратна 997 ₽ → код 51» | реальный эквайринг по тому же контракту |
| ККТ/ФН | эмуляция: ФН/ФД/ФП генерируются, реквизиты ФФД 1.2 | драйвер реестровой ККТ (АТОЛ и др.), [`../plan/02-systems-roadmap.md`](../plan/02-systems-roadmap.md) |
| ОФД | мок: подтверждение приёма через 2–4 с | договор с ОФД, алерт «чеки не уходят» |
| Офлайн | весь срез изначально работает в браузере без сети | норматив 8 часов автономности ([`../product-blueprint.md`](../product-blueprint.md), §5) |

## 4. Критерии успеха пилота (по плану реализации)

1. **Точка живёт без бумаги**: заказы, стоп-лист, чеки и итоги смены — только в системе.
2. **Ни одного чека мимо логики ФНС**: чек существует только при открытой смене и подтверждается ОФД; разрывы видны в журнале.
3. **Стоп-лист расходится во все каналы за секунды** (витрина гостя отражает его без перезагрузки).
4. **Владелец видит день без вопросов**: выручка, средний чек и каналы сходятся с чеками один в один.
5. Персонал осваивает срез **без обучения дольше 15 минут** (наблюдение на точке).

Целевой норматив полного запуска точки — ≤3 рабочих дней ([`../components/09-franchise-network.md`](../components/09-franchise-network.md)); пилотный срез — первый из этих дней.
